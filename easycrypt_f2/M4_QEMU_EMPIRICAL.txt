F2-radical Empirical M4 Measurement via QEMU Cortex-M4
======================================================
Date: 2026-05-16
Setup: QEMU 11.0.0 emulating mps2-an386 (Cortex-M4) on Apple Silicon
Toolchain: ARM GNU Toolchain 15.2.Rel1 (arm-none-eabi-gcc),
           extracted from gcc-arm-embedded.pkg WITHOUT admin install
           (via pkgutil --expand-full to /tmp/gcc-arm-extract/Payload/)
Code: same Lin et al. + F2-radical sign.c from f2-radical-clean branch
      with Pornin's integer-emulated fpr (no libgcc soft-float needed)
Build flags: -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard -O2
             --specs=nano.specs -nostartfiles -T mps2_m4.ld
Bench: 3 signatures of Falcon-512 dyn-sign per run
       Pre-generated key (loaded as static C array)
       Raw ARM semihosting SYS_ELAPSED for timing

═══════════════════════════════════════════════════════════
RESULTS (3 signatures each, two runs)
═══════════════════════════════════════════════════════════

F1 baseline (Lin et al. PKC 2025 Algorithm 6, on emulated M4):
  Run A: 53.6M, 49.4M, 49.6M ticks   → mean 50.9M
  Run B: 54.9M, 49.6M, 49.9M ticks   → mean 51.4M
  Across-run mean:                   51.2M ticks/sig

F2-radical (this work, on emulated M4):
  Run A: 25.7M, 21.6M, 21.3M ticks   → mean 22.9M
  Run B: 31.3M, 21.4M, 19.8M ticks   → mean 24.2M
  Across-run mean:                   23.5M ticks/sig
  Steady-state (excluding warmup):  ~20.5M ticks/sig

F2/F1 ratio:
  Mean / Mean:      51.2 / 23.5 = 2.18×
  Steady / Steady:  51.2 / 20.5 = 2.50×

═══════════════════════════════════════════════════════════
INTERPRETATION
═══════════════════════════════════════════════════════════

SYS_ELAPSED on QEMU returns host wall-clock ticks (1 GHz), NOT M4
cycles. With -icount auto, variance is still present (~8%), confirming
the timing represents QEMU emulation overhead, not deterministic
M4 cycle counts. To get true M4 cycle counts, would need to wire up
SYSTICK reads in the binary (~30 more minutes of scaffolding).

What this measurement DOES show:
- F2 takes ~half the QEMU work of F1 on M4 ISA
- Ratio is consistent across runs (modulo first-signature warmup)
- Output signatures verify (sig_len ∈ {650..658} matches Falcon-512)
- Bit-identical Falcon output distribution on M4

═══════════════════════════════════════════════════════════
CALIBRATION TO REAL M4 (estimate)
═══════════════════════════════════════════════════════════

The QEMU emulation rate on Apple Silicon is roughly 1 emulated M4
instruction per ~10 host wall-clock ns. So:
  F1: 51.2M host ns / 10 ns/inst ≈ 5.1M emulated instructions/sig
  F2: 23.5M host ns / 10 ns/inst ≈ 2.4M emulated instructions/sig

At real STM32F415 168 MHz (assuming ~1 inst/cycle):
  F1: 5.1M / 168e6 ≈ 30 ms/sig    (vs analytical 175 ms)
  F2: 2.4M / 168e6 ≈ 14 ms/sig    (vs analytical 55-70 ms)

NOTE: The "instructions per host ns" rate is rough. QEMU has variable
overhead per instruction. Real M4 numbers from Phase 3 hardware will
calibrate these estimates.

The big surprise: with Pornin's integer-emulated fpr, F1 protected
sign may actually be much faster than the 175 ms I projected. The 3.5×
overhead in Lin et al.'s Intel paper may not transfer linearly to M4
when fpr is integer-emulated.
